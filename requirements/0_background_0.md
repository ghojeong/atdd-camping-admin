# [미션 소개] 스파게티 어드민 시스템

2주차: 스파게티 어드민 시스템에 인수 테스트 작성 with Cucumber

## 미션 배경

급하게 만들어져 기술 부채가 큼 복잡한 레거시 코드에 인수 테스트를 구축합니다.  
기능이 다양하고 레거시 코드가 스파게티처럼 복잡하여 리팩터링은 물론 분석이 어려운 환경에서  
효과적으로 기능을 보호하는 테스트를 구축하고 자신감 있게 리팩터링할 수 있는 환경을 경험을 합니다.

## 시스템 현황

### 기본 정보

* 시스템: 초록 캠핑장 관리자 어드민
* 개발 배경: 급하게 만들어져 기술 부채가 큼
* 현재 문제: 테스트 코드 미비, 높은 코드 복잡도

### 로그인 정보

* 현재 어드민 기능은 인증이 필요합니다.
* 로그인을 통해 토큰을 발급 받은 뒤 요청 마다 토큰을 포함시켜줘야합니다.

### 토큰 요청(로그인)

```java
String adminToken = RestAssured.given()
        .contentType("application/json")
        .body(Map.of("username", "admin", "password", "admin123"))
        .when().post("/auth/login")
        .then().log().all()
        .extract()
        .cookie("AUTH_TOKEN");
```

### 요청에 토큰 포함하기

```java
Map<String, Object> response = given()
        .header("Authorization", "Bearer " + adminToken)
...
```

## 학습 목표

* 인수 테스트를 안전망으로 구축하여 리팩터링 자신감 확보
* Cucumber 기반 기능 명세와 Gherkin 시나리오 작성
* 테스트 재사용성을 높이는 테스트 도구 설계
* 테스트 보호 범위 안에서 레거시 개선 및 신규 기능 가속

## 미션 구성

### Stpe 1: Cucumber를 활용한 인수 테스트 구축

먼저 제공된 기능 후보 중 하나를 선정하여 Gherkin과 Cucumber로 최소 안전벨트를 만듭니다. 선정 근거는 가벼운 리스크 판단으로 기록합니다.

#### 핵심 활동:

* 기능 후보 1가지를 선택하고 보호 대상으로 확정
* Cucumber 베이스라인 세팅: JUnit Runner, features/, Step Definitions, RestAssured 기본 설정
* 선정 기능의 Happy Path 시나리오를 작성하고 통과

### Step 2: 테스트 인프라 확장

시나리오 확장으로 생기는 중복을 제거하고 재사용 가능한 형태로 구조화합니다.

#### 핵심 활동:

* 엣지/예외 케이스 추가: 토큰 누락·만료, 잘못된 상태값, 리소스 미존재, 유효성 오류, 권한 문제 등
* 반복 Step 파라미터화 및 공통 테스트 도구 추출
* 공통 훅(@Before)에서 로그인/공통 헤더 설정, 동적 테스트 데이터로 시나리오 독립성 확보

### Step 3: 인수 테스트의 보호속에서의 리팩터링

구축된 인수 테스트를 안전망으로 레거시를 개선하고, 유사 테스트를 빠르게 추가합니다.  
또 추가로 구현이 필요한 세부 기능을 점진적으로 구현합니다.

#### 핵심 활동:

* 스파게티 포인트를 서비스 계층으로 이관하고 트랜잭션/검증/DTO 도입
    * 예: ReservationAdminController의 상태 변경 → ReservationService
* 유사 신규 기능 가속: 예약 승인/거절, 대여 반납 처리 등
* 경계조건/부정경로 시나리오 추가로 회귀 방지 범위 확대

## 기대 효과

### 실무 적용

* 안전한 리팩터링: 인수 테스트를 안전망으로 자신 있게 변경
* 개발 속도 향상: 테스트 로직 재사용으로 신규 기능 빠른 조립
* 품질 안정성: 회귀 방지 범위 확대와 반복 가능 테스트 기반

### 마인드셋 변화

* "테스트 많이" → 올바른 테스트
* "커버리지" → 비즈니스 가치 중심
* "케이스 나열" → 전략적 선택과 조립
